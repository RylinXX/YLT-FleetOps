# 独立数据库

该查询网站使用独立 SQLite 数据库，不连接或修改主站数据库，不开放数据库网络端口。

生产文件为 `/var/lib/capcloud-api/directory.sqlite`。数据目录由 systemd 的 `StateDirectory=capcloud-api` 管理，目录权限 0700，数据库权限 0600，独立于程序版本目录。部署新版本及重启不会删除数据。需要 Node.js 24 或更新版本。

## 表结构

- `records`：源站记录的稳定键、原始/补充后的源字段、网页展示字段、首次收录/最近确认时间及来源状态。
- `records.local_json`：用户自行补充的私有字段。同步不会覆盖，公共查询接口也不会返回这一列。
- `categories`：各分类的最近成功同步、最近写入、最近尝试、错误及完整性信息。
- `sync_runs`：每次分类同步或零散查询入库的新增、更新、未变、保留、归档数量与结果。
- `record_changes`：源字段变化和来源状态变化，保留最近 90 天、最多 50000 条；同步批次最多保留 10000 条。当前记录及用户补充字段不按此规则删除。

## 同步规则

1. 分类查询只返回数据库记录，不因首次访问、刷新网页或数据变旧而请求源站。北京时间每日 00:00 自动依次同步六类数据；手动点击刷新同步当前分类。同步期间已有数据仍可查询，空数据库提示手动刷新或等待定时同步。
2. 依据“分类 + 来源标识”更新；来源标识重复时使用企业名称/车牌/场所名称、审批区等稳定业务字段区分。源站同企业 ID 存在不同审批批次，企业记录额外使用审批时间区分批次；余量、车辆数或有效期变化不会改变批次记录键。无法可靠区分时停止该批入库并保留旧记录。
3. 新记录插入；已有记录只更新源字段和确认时间，不修改 `local_json`。源站缺省的字段保留最后已知值，明确返回 null 的字段按源站清空。
4. 只有成功取得整批数据后才执行一个事务；失败整体回滚。中途失败不会把半批数据当作同步成功。
5. 完整性核验通过时，本次未返回的旧记录标为 `absent`（历史留档），不会删除。默认网页不把这些记录混入当前查询；它们仍能从数据库查到。
6. 不完整批次里未返回的旧记录标为 `unconfirmed`（待核实）并继续保留展示，页面提示其最近确认时间。来源突然返回空集时也不清空旧数据。
7. 之后重新返回的记录恢复为 `current`，保留首次收录时间和本地补充内容。
8. 接口工作台中成功返回的单页查询也补充入库，但不把其他记录标为缺失，不当作新的完整分类快照。

每日同步由生产应用内的定时器执行，无需浏览器在线；重启仅安排下一个北京时间 00:00，不立即抓取或补跑停机期间的任务。失败保留旧数据，等待手动刷新或次日任务。页面关注功能仍只在浏览器保存标识；本次未新增对外的备注编辑或数据库管理接口。

## 备份与检查

公开的 `/api/api/database/status` 仅提供分类数量和同步状态，不暴露数据库文件路径或私有补充字段。

服务器管理员可以读取概要或生成新的在线一致性备份：

```sh
DATABASE_PATH=/var/lib/capcloud-api/directory.sqlite \
  /opt/capcloud-api/runtime/bin/node /opt/capcloud-api/current/scripts/database-admin.mjs status

DATABASE_PATH=/var/lib/capcloud-api/directory.sqlite \
  /opt/capcloud-api/runtime/bin/node /opt/capcloud-api/current/scripts/database-admin.mjs backup \
  /var/lib/capcloud-api/backups/directory-YYYYMMDD-HHMMSS.sqlite
```

备份命令拒绝覆盖已有文件，完成后运行 SQLite 完整性检查。查询数据含源站公开的法人、联系人等字段，数据库与备份均不得放入站点静态目录或提交到代码仓库。
